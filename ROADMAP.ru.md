# Roadmap: Модернизация Password Generation Utility до Enterprise-уровня

Этот документ содержит пошаговый технический план перевода утилиты автоматизации генерации паролей с исходного уровня на enterprise уровень. План отражает эволюцию проекта от монолитного скрипта к масштабируемому B2B-продукту.

---

## ✅ Спринт 0: Рефакторинг монолита в модульную архитектуру [ВЫПОЛНЕНО]

Цель этапа — уйти от процедурного стиля кода, изолировать компоненты и заложить гибкий интерфейс.

*   **Разделение на модули (Clean Architecture):**
    *   `core.py` — чистая бизнес-логика, полностью изолированная от окон и кнопок.
    *   `view.py` — графическая оболочка, отвечающая только за отрисовку и системные диалоги.
    *   `main.py` — точка входа для сборки и запуска приложения.
*   **Безопасность памяти (Memory Handling):**
    *   Реализована генерация паролей через изменяемый массив байт (`bytearray`).
    *   Внедрена функция `zero_memory_bytearray` для принудительного зануления секретов в RAM сразу после записи на диск (защита от атак на дампы памяти).
    *   Переведен движок генерации со стандартного псевдослучайного `random` на криптографически стойкий `secrets`.
*   **Рефакторинг интерфейса (UI/UX):**
    *   Реализована современная концепция вкладок на базе `CTkTabview` (`Параметры`, `Входные данные`, `Выходные данные`).
    *   Элементы управления избавлены от громоздких серых рамок, добавлен «воздух» и плоская цветовая палитра состояний.
    *   Реализована поддержка динамического ввода ФИО прямо в окне программы и копирования результатов в буфер обмена в один клик.
*   **Защита окружения (Sandbox операции):**
    *   Внедрен метод проверки путей `is_path_forbidden` для блокировки скрытых файлов и системных каталогов (`.venv`, `__pycache__`).
    *   Реализована изоляция файлового ввода-вывода строго внутри папки запуска программы (`BASE_DIR`).
    *   Внедрено автоматическое создание входного файла с демо-данными при первом старте.

## 📌 Спринт 1: Архитектура криптографии и методы оценки (`core.py` + `evaluators.py`) [В ПЛАНЕ]

Цель спринта — обеспечить безопасность отчетов и заложить расширяемый математический движок оценки паролей.

*   **Создание модуля `evaluators.py` (Паттерн «Стратегия»):**
    *   Спроектировать абстрактный базовый класс `PasswordEvaluator` с помощью модуля `abc`.
    *   Реализовать первую конкретную стратегию — класс `ShannonEntropyEvaluator` для расчета информационной энтропии по формуле:
        $$H = -\sum (P_i \log_2 P_i)$$
    *   Изолировать математику оценки от ядра генератора, обеспечив возможность будущей смены или добавления новых методов (ГОСТ, NIST).
*   **Криптографический модуль защиты (AES-256) в `core.py`:**
    *   Интегрировать библиотеку `cryptography` для защиты результирующих файлов.
    *   Реализовать деривацию безопасного ключа шифрования из мастер-пароля пользователя с использованием алгоритма `PBKDF2` и соли (`salt`).
    *   Обеспечить симметричное шифрование файлов по стандарту AES-256 перед их записью на диск.
*   **Расширение конфигураций генератора:**
    *   Модернизировать класс `PasswordConfig` в `core.py`, добавив методы жестких пресетов политик безопасности (`Standard`, `Enterprise`, `Ultra`).

## 📌 Спринт 2: Новая структура интерфейса и системная вкладка (`view.py`) [В ПЛАНЕ]

Цель спринта — провести рефакторинг UI/UX, разгрузить рабочее пространство и подготовить интерфейс к расширению.

*   **Рефакторинг координационной сетки (Tabview):**
    *   Перестроить интерфейс на базе виджета `CTkTabview` на 4 постоянные изолированные вкладки:
        1.  `⚙️ Parameters` (настройки сложности и пресеты).
        2.  `📥 Input Data` (выбор источника ФИО).
        3.  `📤 Output Data` (выбор назначения паролей и шифрование).
        4.  `🛠️ Settings` (системные параметры приложения).
*   **Вкладка «Настройки» (Settings):**
    *   Перенести на новую вкладку логику динамического переключения локализации интерфейса (RU / EN).
    *   Добавить выпадающее меню смены темы оформления (Тёмная / Светлая / Системная) с вызовом `ctk.set_appearance_mode`.
    *   Добавить `CTkOptionMenu` для динамического выбора стратегии оценки пароля, которая будет запрашиваться из `evaluators.py`.
*   **Реактивный UI политик безопасности и оптимизация лимитов:**
    *   Добавить `CTkOptionMenu` для выбора пресетов на вкладку «Parameters».
    *   Реализовать автоматическую программную блокировку (`state="disabled"`) и перемещение ползунков на заданные позиции при выборе готовой политики.
    *   **Ограничение длины:** Уменьшить максимальный предел каждого ползунка символов (заглавные, строчные, цифры, спецсимволы) с 10 до 8. Это зафиксирует максимальную длину генерируемого пароля на отметке в 32 символа ($8 \times 4 = 32$).

## 📌 Спринт 3: Модуль парсинга и интеграция данных (`parsers.py`) [В ПЛАНЕ]

Цель спринта — адаптировать утилиту под сложные структурированные форматы данных компаний без изменения бизнес-логики генератора.

*   **Создание изолированного модуля `parsers.py`:**
    *   Реализовать пакетный импорт структурированных таблиц (Excel / CSV) с помощью библиотеки `pandas`.
    *   Полностью изолировать логику чтения файлов от файлов `core.py` и `view.py` для обеспечения слабой связанности компонентов.
*   **Динамический маппинг колонок (Dynamic Mapping):**
    *   Реализовать в `view.py` чтение только первой строки (заголовков) таблицы при её загрузке.
    *   Обеспечить автоматический вывод названий колонок в выпадающий список (`CTkOptionMenu`) на вкладке `Input Data`. Пользователь должен сам указывать, какая колонка содержит ФИО сотрудников.
*   **Потоковый парсинг датафреймов:**
    *   Модернизировать метод `process_files` во `view.py` для работы с новым модулем `parsers.py`.
    *   Обеспечить корректное извлечение данных, генерацию паролей и обратную упаковку результатов в выбранный формат.

## 📌 Спринт 4: Безопасный UX и Шифрование (`view.py` + `core.py`) [В ПЛАНЕ]

Цель спринта — связать графическую оболочку с криптографическим ядром, обеспечив интерактивное управление защитой отчетов.

*   **Интерактивный шифровальный фрейм на вкладке `Output Data`:**
    *   Добавить чекбокс «Зашифровать» (`Encrypt report`).
    *   Связать состояние чекбокса с доступностью поля ввода мастер-пароля. При снятом чекбоксе поле ввода должно полностью блокироваться (`state="disabled"`), очищаться и становиться серым. При включении — переходить в режим `"normal"`.
*   **Строгая валидация секретов:**
    *   Внедрить UI-валидацию, которая блокирует кнопку «Запустить генерацию» и подсвечивает поле ввода красным цветом, если чекбокс шифрования включен, но мастер-пароль остался пустым.
*   **Связывание с крипто-ядром:**
    *   Обеспечить безопасную передачу мастер-пароля в модуль AES-256 (из Спринта 1) для выполнения симметричного шифрования файла результатов перед его непосредственной записью на диск.

## 📌 Спринт 5: Математический UI-Скорринг и Визуализация Энтропии (`view.py` + `evaluators.py`) [В ПЛАНЕ]

Цель спринта — внедрить честную аналитическую оценку стойкости пароля и динамически отображать её пользователю.

*   **Связывание UI с математическим модулем:**
    *   Подключить выбранную на вкладке `Settings` стратегию оценки пароля (из модуля `evaluators.py`) к слушателям ползунков символов во `view.py`.
*   **Реактивный индикатор (Strength Bar):**
    *   Настроить индикатор `strength_bar` так, чтобы он мгновенно реагировал на изменение математической энтропии при каждом сдвиге бегунков.
*   **Градиент состояний:**
    *   Реализовать плавное изменение цвета полосы прогресса (красный -> оранжевый -> зеленый -> бирюзовый) на основе реального битового веса сгенерированной структуры пароля, а не его длины.

## 📌 Спринт 6: Модуль автоматической рассылки и Enterprise-доставки (`delivery.py`) [В ПЛАНЕ]

Цель спринта — автоматизировать безопасную дистрибуцию конфиденциальных данных до конечных сотрудников через корпоративные каналы связи.

*   **Создание изолированного модуля `delivery.py`:**
    *   Реализовать класс `EmailDeliveryService` для пакетной отправки писем, используя исключительно встроенные, «легкие» библиотеки Python `smtplib` и `email.mime` (сохраняя неизменным вес и независимость итогового скомпилированного приложения).
*   **Интерактивный UI рассылки на вкладке `Output Data`:**
    *   Добавить чекбокс «Отправить доступы на Email» (`Send via Email`).
    *   Реализовать скрытый фрейм с параметрами подключения, который плавно раскрывается только при включении чекбокса. Поля для ввода: `SMTP-сервер`, `Порт`, `Email отправителя`, `Пароль приложения (App Password)`.
*   **Интеграция с парсером таблиц:**
    *   Связать модуль рассылки со Спринтом 3 (`parsers.py`). При пакетном импорте Excel/CSV таблиц программа должна автоматически сопоставлять колонку ФИО с колонкой Email сотрудника и отправлять сгенерированный пароль индивидуально каждому человеку.
    *   Гарантировать, что сразу после отправки все пароли полностью стираются из памяти RAM, а на диске админа не остается открытых текстовых файлов с доступами сотрудников.
